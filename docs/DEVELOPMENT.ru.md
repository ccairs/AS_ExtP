## 1. Техническая архитектура

Архитектура AS_ExtP: **панель CEP (CEF / Chrome 88) + локальный Bridge на Node**:

```
Панель CEP (CEF, file://)
  │  8 функциональных модулей + features (панель быстрого доступа / питомец / индикатор внешней авторизации)
  │  Общий/базовый уровень: AEFS · Bridge · ToolRegistry · шлюз AST (PromptBuilder в client/llm/, ContextManager в client/modules/agent/engine/, контекст контейнера в client/core/)
  ├── CSInterface.evalScript()  ──►  движок AE (host.jsx + host/api/*.jsx) выполняет ExtendScript
  ├── Node Bridge (127.0.0.1:9877, HTTP + WebSocket)
  │     ├─ файловая система (полное чтение и запись, включая бинарный канал)
  │     ├─ управление внешними процессами MCP
  │     └─ конечная точка /mcp (транспорт Streamable HTTP внешнего режима)
  └── Внешний режим: внешний агент ⇄ stdio / HTTP ⇄ Bridge relay ⇄ панель ⇄ AE
```

- **Файловая система (AEFS)**: `client/shared/aefs.js` даёт единое чтение и запись файлов и использует многоуровневый откат **Bridge → cep.fs → ExtendScript**, а для путей выполняет многоуровневые проверки безопасности (отклоняются `%`, управляющие символы, обход через `..`, неабсолютные пути, имена устройств DOS; операции записи и удаления ограничены белым списком безопасных каталогов).
- **Шлюз компиляции AST**: любой сценарий, созданный ИИ или сохранённый пользователем, перед выполнением проходит единый статический шлюз компиляции — предобработка диалекта ExtendScript → разбор acorn (ES3) → проверка типов и членов по белому списку → повторная эмиссия и выполнение. Проверяется и выполняется один и тот же код, окна «правка после проверки» нет. Все четыре входа (вызовы инструментов Agent, область предпросмотра, определения инструментов JSON, дерево скриптов / панель быстрого доступа) сходятся здесь; опасные конструкции блокируются на стороне шлюза и возвращаются модели на переписывание. Доверие каналу, переключатели доменов возможностей и таблицу дополнений белого списка можно посмотреть в «Настройки модуля Agent → Настройка возможностей шлюза AST». Дерево скриптов / панель быстрого доступа (`user-library`) идут в режиме аудита: шлюз лишь формирует список опасных конструкций и не переписывает код (см. `client/modules/ast-gate/run.js`).
- **Каталог данных**: корень расширения доступен только для чтения, рабочие данные хранятся в `%APPDATA%\Adobe\CEP\extensions\AS_ExtP` (сценарии, навыки, память, инструменты, эффекты, шаблоны настроек и т. п.). В общих настройках путь можно сменить на произвольный: переключение = **полное копирование** (если в целевом каталоге уже есть данные, сначала выводится подтверждение перезаписи, после подтверждения старые данные удаляются и выполняется копирование); в завершение абсолютные пути в скопированном **индексе библиотеки** (`assets/<библиотека>/*.json`), начинающиеся со старого корня, **переписываются на новый корень** — иначе при запуске в новом каталоге сканирование диска сочтёт одноимённые файлы «неучтёнными» и продублирует их в библиотеке (для шаблонов настроек и ассетов проекта такие случаи были); старый каталог не удаляется автоматически, пользователь проверяет и очищает его сам. **При добавлении библиотеки**: не храните в индексе абсолютные пути файлов библиотеки (храните относительные или вычисляйте их во время работы от каталога данных); если абсолютный путь всё же нужен, при миграции нужно выполнить такое же переписывание (см. `rebaseLibraryIndexPaths` в `client/shared/dataDir.js`).
- **Шина промптов**: итоговый промпт для LLM собирается из четырёх слоёв (каркас System Prompt → конвейер PromptBuilder → вставка истории сообщений → обёртка User Prompt); модули участвуют через стандартные точки внедрения и не собирают строку напрямую.
- **Node Bridge**: обслуживает файловые операции и управление процессами MCP, при простое завершается сам, а при открытой панели удерживается сигналом heartbeat. Конечная точка HTTP внешнего режима и вход stdio используют одно ядро протокола; вызовы инструментов выполняются последовательно через панель (сценарный движок AE однопоточный).
- **Журнал диагностики**: журналы процессов панели / Bridge / хоста / нативных компонентов используют единый формат времени ISO и единый предел размера файла (строки ошибок Bridge дополнительно помечаются `[ERR]`); при экспорте диагностического пакета выполняется единое обезличивание и свёртка повторяющихся строк по сигнатуре (по одной сигнатуре сверх порога остаётся только первая строка с указанием общего числа повторов и временного интервала). Экспорт доступен в общих настройках.

### Список исключений AEFS

Файловый ввод-вывод на стороне панели (CEP) всегда идёт через AEFS; после проверки всего репозитория исключения сосредоточены на стороне host / ExtendScript — всего **две категории и семь точек вызова удаления файлов** (в JS панели исключений нет):

1. **Самоочистка цепочки запуска (5 мест, структурно не могут идти через AEFS)**: `_sweepHandoffLeftovers` в `host/host.jsx` (уборка бесхозных маркеров передачи, vbs и сценариев обнаружения нескольких экземпляров `.axd`), удаление `vbsFile` в конце `startBridge`, удаление записанного этим же запуском сценария-детектора `.axd` в `_runAxDetectionProbe`, удаление `ae_extp_multi_instance.json` в `_clearMultiInstanceMarker`, удаление файла рукопожатия при отсутствии ошибок в `_writeHostLoadErrors` — AEFS это модуль стороны панели, а его интерфейс удаления зависит от Bridge / CEP, тогда как эти вызовы выполняются именно тогда, когда «Bridge ещё нет», или на завершающем этапе самопроверки запуска. Путь = каталог данных `temp/handoff` (с резервом на системный временный каталог); удаляются только файлы, созданные самой цепочкой запуска (маркеры передачи / vbs / сценарии-детекторы `.axd`, маркер нескольких экземпляров, отчёт об ошибках прошлой загрузки); защита = регулярное выражение по точному имени файла, удаление только файлов (одноимённые каталоги пропускаются), уборочные элементы удаляют лишь остатки с `mtime` старше 10 минут.
2. **«Сначала очистить, затем скопировать» в процессе экспорта (2 места, по порядку выполнения лучше не идти через AEFS)**: по одному месту в `exportWholeProject` / `exportCompOrLayer` из `host/api/projectAssetApi.jsx` — перед повторным копированием одноимённого видеоряда удаляется старая копия внутри пакета. Точка удаления находится в середине процесса на стороне ES (до копирования), и передача её панели внесла бы «гонку между очисткой и экспортом»; поэтому удаление оставлено на стороне host, но перед ним `_ensureUnderRoot(dstPath, footageDir.fsName)` повторяет `_checkPath` из AEFS и проверку контейнера (отклоняются `%`, управляющие символы, кавычки, имена устройств DOS, сегменты `..`; путь обязан быть подкаталогом footageDir), а при выходе за границы только пишется журнал без удаления.

## 2. Подготовка и проверка окружения

> **У двух способов получения разные предпосылки**: **полный пакет Release работает сразу** (уже включает среду выполнения Node, зависимости npm и предкомпилированные `.aex`) — распакуйте архив и дважды щёлкните `tools\install.bat`, развёртывание на этом закончено, и этот раздел можно пропустить; **клон исходников сразу не работает**: нужны Node, `npm ci`, `check-env.bat` (скачивает Node / ffmpeg) и при необходимости сборка нативных компонентов.

- Node.js **≥ 20.18** (CEF на стороне панели — Chrome 88 без среды выполнения Node: внутри панели `require` / `process` не существуют, файловый ввод-вывод идёт только через AEFS)
- Установка зависимостей: `npm ci`; или дважды щёлкните `tools\check-env.bat` (по пунктам проверяет Node, зависимости, ffmpeg и версию AE и подсказывает, что дополнить)
- `npm run lint` — проверка ESLint (`eslint.config.js`)
- `npm run audit:theme` / `npm run audit:family` — аудит жёстко заданных цветов темы и вымерших семейств режимов отказа (контрольная проверка CI)
- CI публичного репозитория (`.github/workflows/ci.yml`) состоит из двух заданий: `lint-and-audits` выполняет `npm ci` → `lint` → два аудита; `release-tree-check` на чистом клоне без зависимостей выполняет `node tools/release-check.js --public . --public-only` (в публичном дереве нет бинарников, нет `node_modules` / `vendor`, NOTICES полные). Любой упавший шаг даёт красный статус

## 3. Развёртывание в CEP

У двух сценариев разные обязанности:

- **Первая установка / обычные пользователи**: дважды щёлкните `tools\install.bat`. Сценарий сам находит установленный AE, скачивает Node и ffmpeg, записывает `PlayerDebugMode` и при обнаружении `deploy\Plug-ins\*.aex` автоматически разворачивает нативные компоненты.
- **Обновляющее развёртывание в период разработки**: после правок `host` / `client` / `CSXS` или нативных компонентов дважды щёлкните `tools\deploy.bat` (нужны права администратора; копирует эти элементы в `C:\Program Files (x86)\Common Files\Adobe\CEP\extensions\AS_ExtP`). Скачиванием и настройкой реестра он не занимается, требует наличия `vendor\`; если его нет, предлагает сначала запустить `tools\check-env.bat`.

Оба сценария при отсутствии `vendor\node_modules` дополняют его копированием из корневого `node_modules` каталога исходников — развёрнутый Bridge разрешает зависимости из `vendor\node_modules` (разбор вложений docx / xlsx / pdf).

## 4. Локализация (Localization)

Интерфейс панели локализуется небольшой средой выполнения и сгенерированными языковыми пакетами. Китайский исходный текст служит ключом (`t('源文')`), поэтому непереведённые строки откатываются к китайскому исходнику, а не исчезают.

> `i18n/`, `tools/i18n/` и `tests/` существуют только в репозитории мейнтейнера и не попадают в публичное дерево; публичное дерево содержит только сгенерированные языковые пакеты в `client/shared/i18n/locales/`. Приведённые ниже команды предназначены для мейнтейнеров.

### Выбор языка

- Общие настройки → **Язык интерфейса** (`globalUiLocale`): хранится вместе с остальными общими настройками под `uiLocale` и дублируется в `localStorage['ae_ui_locale']`, откуда значение берётся при запуске.
- Варианты: **Следовать языку интерфейса After Effects** (`auto`), 简体中文 (`zh-CN`), English (`en-US`), 日本語 (`ja-JP`), Deutsch (`de-DE`), 한국어 (`ko-KR`), Français (`fr-FR`), Русский (`ru-RU`).
- `auto` разрешается через `getHostEnvironment().appLocale` из CEP, при неудаче выполняется откат к `navigator.language`. Известный, но неподдерживаемый язык хоста разрешается как `en-US`; если прочитать не удалось, остаётся `zh-CN`.
- Сохранение другого значения перезагружает панель (об этом сказано в строке настроек); других шагов не требуется.

### Файлы

| Путь | Назначение |
| --- | --- |
| `i18n/keys.json` | все ключи, которые запрашиваются в среде выполнения (строковые литералы `AEI18n.t(...)` / `AEI18n.html(...)` плюс текст из `client/index.html`), генерируется `scan-keys.js` |
| `i18n/translations/en-US.json` | перевод для `en-US` (исходный текст → перевод) |
| `client/shared/i18n/locales/en-US.js` | сгенерированный языковой пакет, загружается статически |
| `client/scripts.manifest.js` | порядок загрузки: языковой пакет идёт первым в группе i18n и через `AEI18nPending` передаёт словарь в `i18nCore` |
| `client/shared/i18n/i18nCore.js` | среда выполнения: `t` / `html` / `err`, разрешение языка, статический перевод DOM |
| `client/shared/i18n/i18nHtml.js` | собирает и переводит текстовые узлы и атрибуты из белого списка в шаблонах HTML |
| `client/shared/i18n/errorCodes.js` | таблица сообщений кодов ошибок |

`i18n/` и `tools/i18n/` используются только на стороне разработки и не попадают в публичное дерево; публичное дерево содержит только сгенерированные языковые пакеты в `client/shared/i18n/locales/`.

### Команды

```bash
node tools/i18n/scan-keys.js                 # повторное сканирование дерева исходников → i18n/keys.json
node tools/i18n/build-locale.js en-US        # проверка перевода → client/shared/i18n/locales/en-US.js
node tools/i18n/check-coverage.js en-US      # контрольная проверка: все ключи на месте, лишних нет (при расхождении код выхода 1)
```

`build-locale.js` не записывает файл и завершается с кодом 1, если перевод пуст, набор `{placeholder}` не совпадает с исходным текстом или ключ отсутствует в `keys.json`. После правки текстов интерфейса выполните в репозитории мейнтейнера эти три команды в указанном порядке, затем `npm test` и `npm run lint`.

### Поддерживаемые языки

`zh-CN` (исходный текст), `en-US`, `ja-JP`, `de-DE`, `ko-KR`, `fr-FR`, `ru-RU`. Среда выполнения принимает все семь идентификаторов; селектор языка в панели всегда перечисляет семь пунктов независимо от того, какие языковые пакеты реально поставляются с пакетом. `en-US`, `ja-JP`, `de-DE`, `ko-KR`, `fr-FR`, `ru-RU` укомплектованы полностью (по 3450 ключей, покрытие 100%).

### Область действия и ограничения

- **Строка фактов об окружении (`ENV_LINE`, формируется `envLine()` из `client/modules/agent/engine/prompts.js`)**: системный промпт указывает язык интерфейса хостового AE (`中文版` / `英文版` / `日文版` / `德文版` / `韩文版` / `法文版` / `俄文版`), значение берётся из `getHostEnvironment().appLocale`; единственный источник — `client/modules/agent/engine/prompts.js`. Строка описывает факт о хосте и не связана ни с языком интерфейса панели, ни с языком ответов модели.
- **Сообщения ExtendScript**: ошибки, выбрасываемые `host/*.jsx`, остаются на китайском. Они передаются через `CSInterface.evalScript()` простой строкой и не участвуют в согласовании языка, поэтому при английском интерфейсе эти сообщения всё равно выводятся по-китайски; локализуется только сопоставление кодов ошибок на стороне панели.
- **Диагностика шлюза AST**: `error.reason` / `error.alternative` из `client/modules/ast-gate/` остаются на китайском — это вход для самопочинки LLM (`llmText`). При языке интерфейса, отличном от исходного, поверхность панели (строка состояния, карточка ошибки выполнения, панель быстрого доступа) показывает локализованные типовые фразы из `client/shared/i18n/gateReasons.js`; исходные подробности на китайском видны только при выбранном языке интерфейса «упрощённый китайский».
- **Сценарии установки**: `tools/install.bat`, `tools/check-env.bat` и `tools/deploy.bat` выводят только ASCII-английский (сценарии переключаются на `chcp 437`). Комментарии в сценариях могут быть на китайском; в публичном дереве технические комментарии сохраняются, а повествовательные переписываются или удаляются по карте комментариев релиза.
- **Интерфейс нативного компонента**: видимый пользователю текст в `native/hotbox` (AS_Hotbox) и `native/glsl-host` (AS_Effect Host) — фильтры и настройки Hotbox, имена параметров эффектов, «О программе», окна ошибок, диалоги выбора файлов — следует **языку интерфейса хостового After Effects** (`PF_AppGetLanguage`) и не зависит от языка интерфейса панели; при неподдерживаемом языке хоста используется английский, при невозможности прочитать язык хоста — китайский. Журналы и внутренняя диагностика не переводятся; предупреждения с техническим токеном (например, `[uniform limit reached]`) остаются на английском; остальные предупреждения для пользователя локализованы.

## 5. Сборка нативных компонентов

Оба нативных компонента — проекты C++ / CMake, **требуются Visual Studio 2022 (с MSVC) и Adobe After Effects SDK**; SDK по своей лицензии не распространяется вместе с репозиторием, его нужно получить у Adobe самостоятельно.

### 5.1 Хост GLSL-эффектов (`native/glsl-host/`)

```powershell
cmake -S native/glsl-host -B native/glsl-host/build -DAEFX_SDK_PATH="<путь к SDK AE>"
cmake --build native/glsl-host/build --config Release
```

### 5.2 AE Hotbox (`native/hotbox/`)

```powershell
cmake -S native/hotbox -B native/hotbox/build -DAEFX_SDK_PATH="<путь к SDK AE>"
cmake --build native/hotbox/build --config Release
```

Результат по умолчанию выводится в `deploy/Plug-ins/` (можно переопределить через `-DAE_PLUGIN_OUTPUT=<каталог>`). Скопируйте `.aex` в каталог AE `Support Files\Plug-ins\` и **полностью закройте и перезапустите AE** — после этого изменения вступят в силу. Модульные тесты нативной логики запускаются `ctest` в каталоге сборки и не требуют участия AE.

## 6. Материалы по разработке Hotbox

> Этот раздел описывает сборку / развёртывание / устранение неисправностей Hotbox; пользовательское описание — в разделе README «Нативные компоненты → AE Hotbox».

#### Сборка .aex

Требования: SDK AE 2023+, Visual Studio 2022, CMake 3.20+.

```powershell
# в корне репозитория
cmake -S native/hotbox -B native/hotbox/build `
  -DAEFX_SDK_PATH="<путь к SDK AE>" `
  -DAE_PLUGIN_OUTPUT="<репозиторий>\deploy\Plug-ins"
cmake --build native/hotbox/build --config Release
```

Результат: `deploy\Plug-ins\AS_Hotbox.aex`.

#### Развёртывание в AE

1. **Полностью закройте AE** (новый подключаемый модуль загружается только после перезапуска).
2. Скопируйте `AS_Hotbox.aex` в каталог AE `Support Files\Plug-ins\`:

```powershell
Copy-Item "<репозиторий>\deploy\Plug-ins\AS_Hotbox.aex" `
  "<каталог установки AE>\Support Files\Plug-ins\" -Force
```

3. Убедитесь, что расширение CEP развёрнуто (`tools\deploy.bat` или `tools\install.bat`): Hotbox читает сценарии и индекс шаблонов настроек из каталога данных расширения, а также читает напрямую каталоги шаблонов настроек самого AE (правила поиска — ниже, в разделе «Источники данных»).
4. Запустите AE.

#### Проверка загрузки

После запуска AE откройте журнал `<каталог данных>\temp\logs\as_hotbox.log`; в нём должно быть:

```
EntryPointFunc OK
window: init ok
hotkey: registered Alt+Q
```

Если горячая клавиша занята, в журнале появится `hotkey: configured ... in use, fallback default` и произойдёт откат к `Alt+Q`; если занята и `Alt+Q`, появится `hotkey: default Alt+Q also failed` — подключаемый модуль всё равно загрузится, но горячая клавиша работать не будет (нужно сменить её в панели настроек).

---


#### Файл конфигурации

Конфигурация хранится в `<каталог данных>\hotbox\config.json`:

```json
{
  "gesture": {
    "slots": [
      null,
      {"type":"effect","key":"ADBE Gaussian Blur 2","name":"高斯模糊"},
      null,
      null,
      null,
      {"type":"script","key":"C:\\abs\\path\\script.jsx","name":"脚本"}
    ]
  },
  "hotkey": {"mods": 1, "vk": 81},
  "releaseExecute": true,
  "releaseStay": false
}
```

- `slots`: взаимно однозначно соответствует 6 дугам кольца жестов (`null` = динамический слот). Верхняя (снимок экрана) и нижняя (настройки) дуги выделены и не участвуют в привязке слотов; 4 строки панели настроек соответствуют остальным 4 дугам (слева сверху / слева снизу / справа сверху / справа снизу), соответствие дуг и индексов массива фиксировано раскладкой.
- `hotkey.mods`: битовые флаги, 1=Alt 2=Ctrl 4=Shift (как `MOD_*` в Win32).
- `hotkey.vk`: код виртуальной клавиши (например, 81 = 'Q').
- `releaseExecute`: выполнять ли выбранную дугу при отпускании сочетания клавиш (строка 5 настроек, по умолчанию true).
- `releaseStay`: оставаться ли плавающему окну открытым после отпускания сочетания клавиш (строка 6 настроек, по умолчанию false; применение — в README, раздел «AE Hotbox»).

Список недавних хранится в `<каталог данных>\hotbox\recent.json`.

> **Каталог данных** по умолчанию — `%APPDATA%\Adobe\CEP\extensions\AS_ExtP`.

---

### Источники данных

Hotbox читает локальные файлы напрямую (AEGP работает в одном процессе с AE; Bridge не нужен, и панель расширения не обязана быть открытой):

| Данные | Источник | Описание |
|------|------|------|
| Эффекты | нативное перечисление AEGP (`AEGP_EffectSuite4`) | таблица установленных эффектов в памяти AE, тот же источник, что у меню «Эффект»; берутся отображаемое имя + matchName |
| Сценарии | `agent\scripts\` рекурсивно | `.jsx` / `.jsxbin` |
| Шаблоны настроек (библиотека расширения) | `assets\presets\index.json` | `.ffx`, добавленные в библиотеку панелью (сами файлы лежат в каталоге библиотеки); имя + папка + путь к ffx |
| Шаблоны настроек (заводские AE) | `<AE>\Support Files\Presets\` рекурсивно | тот же источник, что у панели AE «Эффекты и шаблоны» |
| Шаблоны настроек (пользовательские AE) | `文档\Adobe\After Effects <версия>\User Presets\` рекурсивно | место сохранения команды AE «Сохранить шаблон настроек анимации»; отсутствующий каталог не учитывается |

- **Слияние трёх источников шаблонов настроек**: приоритет = библиотека расширения > пользовательские шаблоны AE > заводские шаблоны AE; ключ дедупликации = имя в нижнем регистре + размер файла в байтах, то есть
  «одно имя и один размер = одна и та же копия шаблона» (при добавлении в библиотеку панель копирует `.ffx` побайтово, поэтому копия совпадает с источником по имени и размеру).
  Дедупликация только по имени недопустима: среди заводских шаблонов AE действительно есть пары с одинаковым именем и разным содержимым (например, «百叶窗» — 191231/26526 байт и
  «放大» — 43417/75976 байт), и отбор только по имени проглотит реальные записи. Записи со стороны AE только читаются и не копируются, применение идёт через
  `layer.applyPreset(File)`, тем же путём, что и для шаблонов из библиотеки (поэтому шаблоны AE тоже можно привязать к слотам кольца жестов).
- **Размер на стороне библиотеки берётся из реального файла**: `size` в индексе — снимок на момент добавления в библиотеку; при перезагрузке он выверяется по фактическому числу байт файла;
  если файла уже нет (или путь указывает на каталог), значение считается «неизвестным» — устаревшее значение не используется для свёртки реальных записей AE с тем же именем и размером,
  иначе после удаления `.ffx` из библиотеки в Hotbox останется запись, применение которой заведомо не удастся, а рабочий шаблон AE будет ею вытеснен.
- **Архивные записи в Hotbox не попадают**: записи с `archived=true` в индексе (сам файл уже перенесён в `___archive__` и физически удаляется через 7 дней)
  исключаются по тому же правилу, что и в панели быстрого доступа, чтобы они не вытесняли реальные записи AE с тем же именем.
- **Поиск каталогов шаблонов настроек AE**: сначала путь выводится из пути модуля самого подключаемого модуля (`<AE>\Support Files\Plug-ins\...` → корень установки),
  и только при установке в нестандартное место вроде MediaCore выполняется откат к `app.path` AE (тот же источник, что у
  `getInstallPath` из расширения `ae-tools`). Если не удаётся получить ни один из двух путей, используется только библиотека расширения, остальные функции не страдают.
- Список эффектов перечисляется внутри процесса AE (без ExtendScript и без чтения индекса с диска): только что установленный подключаемый модуль находится через поиск без создания какого-либо кэша.
- `ae-tools\effects_cache.json` больше не основной источник списка эффектов и используется как резерв, только когда нативное перечисление вернуло пустой результат (AEGP не готов).
- Правило обновления: если сигнатура источников данных (число установленных эффектов + mtime `index.json` + дерево каталога сценариев + деревья двух каталогов шаблонов настроек AE) не изменилась,
  при повторном вызове напрямую переиспользуются список и индекс по пиньиню из памяти; добавление, удаление и правка сценариев или шаблонов настроек, а также сохранение шаблона настроек в пользовательский каталог из AE
  приводят к несовпадению сигнатуры и автоматической перезагрузке (перезапуск AE не нужен). Обход для сигнатуры выполняется при каждом показе, полное сканирование заводского каталога — только при несовпадении сигнатуры,
  обе операции линейны по числу записей шаблонов настроек и сценариев и не накапливаются с числом показов.
- После загрузки подключаемого модуля при первом простое (≥2 с) данные один раз прогреваются (перечисление + индекс по пиньиню), чтобы стоимость первой загрузки не попадала в путь обработки нажатия.

#### Ограничения кодировки

- Внутренние пути и имена проекта — всегда узкие строки UTF-8; файлы всегда открываются через широкосимвольный API (`utf8ToWide` из `native/hotbox/src/data.h` и вызовы широких путей в `log.h`) — узкий путь `char*` система интерпретирует как ANSI/GBK, и путь с китайскими символами не откроется.
- Строки `A_char` AEGP (имена и категории эффектов) по соглашению SDK используют системную ANSI; по одной строке кодировку определить нельзя, поэтому пакет данных сначала целиком проверяется на ANSI / UTF-8 и лишь затем декодируется (`isAnsiBatch` / `ansiToUtf8` в `data.h`). Новые источники данных должны следовать тому же правилу: не считайте `A_char` сразу UTF-8 и не склеивайте из неё путь напрямую.

### Устранение неисправностей

#### Расположение журнала

`<каталог данных>\temp\logs\as_hotbox.log` — записывает загрузку подключаемого модуля, регистрацию горячей клавиши, результаты выполнения и сообщения об ошибках. Каталог данных по умолчанию — `%APPDATA%\Adobe\CEP\extensions\AS_ExtP` (см. раздел «Файл конфигурации»); при смене каталога данных журнал переезжает вместе с ним.

#### Частые вопросы

| Симптом | Что проверить |
|------|------|
| Нажатие горячей клавиши ничего не делает | проверьте журнал: успешно ли `hotkey: registered ...`; в фокусе ли AE (без фокуса не срабатывает) |
| Горячая клавиша занята | в журнале появляется `hotkey: configured ... in use, fallback default` (откат к сочетанию по умолчанию) или `hotkey: default Alt+Q also failed`; запишите новое сочетание в панели настроек. Если при записи нажатие **вообще не реагирует**, сочетание занято другой программой (нажатие перехватывается на системном уровне и не доставляется): смените сочетание или закройте занявшую его программу |
| Плавающее окно показывает `扩展未启动` | расширение CEP не развёрнуто; запустите `tools\deploy.bat` или откройте панель AS_ExtP в AE |
| Поиск ничего не находит | введено ли ключевое слово (пустой запрос не выдаёт записей); есть ли сценарии в `agent\scripts\`; существует ли `assets\presets\index.json` |
| Не удаётся применить эффект | выбран ли слой; открыта ли композиция |
| Плавающее окно не закрывается после отпускания сочетания клавиш | в панели настроек включено «`松手停留` (Задержка после отпускания)» (в config.json — `releaseStay`); закройте через Esc, щелчком вне окна или повторным нажатием горячей клавиши либо выключите её в панели настроек |
| Падение при закрытии AE | проверьте, есть ли в журнале `DeathHook`; проверьте просмотр событий |
| Неверное положение на нескольких мониторах | плавающее окно ограничивается рабочей областью монитора, где находится мышь; на дополнительном экране оно не должно выходить за его пределы |
| Сбои ввода на китайском | поле поиска использует элемент Win32 EDIT, подсказки и кандидаты IME работают; Enter во время набора не выполняет раньше времени |

#### Процесс повторного развёртывания

После правки кода C++:

```powershell
# 1. Выйдите из AE
# 2. Пересоберите
cmake --build native/hotbox/build --config Release
# 3. Скопируйте .aex в AE (с заменой)

# 4. Запустите AE (нужен полный перезапуск; в диспетчере задач убедитесь, что процесс AfterFX.exe завершён)
```

После правки ExtendScript (`host/api/effectApi.jsx` и т. п.):

```powershell
# запустите deploy.bat, чтобы обновить файлы host в каталоге расширения CEP
tools\deploy.bat
# перезапускать AE не нужно: новый сценарий загрузится при следующем вызове
```

### Техническая архитектура

```
┌──────────────────────────────────────────────────────────────────────────────────────────────┐
│ native/hotbox/  AEGP-плагин (C++20 + MSVC, GeneralPlug)                                      │
│  ├─ хоткей       RegisterHotKey + скрытое окно сообщений ← WM_HOTKEY                         │
│  │              → GetCursorPos: координаты мыши                                              │
│  ├─ плавающее окно  WS_POPUP + WS_EX_TOPMOST + прозрачность многослойного окна               │
│  │              ├─ режим жестов: центральный круг + кольцо дуговых сегментов (Direct2D)      │
│  │              └─ режим поиска: длинная панель поиска + линейный список + выпадающий фильтр │
│  ├─ канал выполнения  AEGP_UtilitySuite6::AEGP_ExecuteScript                                 │
│  │              → effectApi.jsx / scriptRunner.jsx                                           │
│  └─ данные      чтение прямо в процессе: std::ifstream + GetFileAttributesW                  │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Ключевые ограничения:
- Канал выполнения `AEGP_ExecuteScript` синхронно блокирует главный поток AE → предпочтительны короткие сценарии, во время выполнения показывается индикатор состояния.
- Чтение и запись данных идут не через Bridge: подключаемый модуль читает файл конфигурации и индекс сценариев в каталоге данных прямо в своём процессе, Bridge обслуживает только сторону панели.
- Выполнение сценариев всегда идёт через обёртку песочницы (`runScriptSandboxed`), обходного переключателя нет.
