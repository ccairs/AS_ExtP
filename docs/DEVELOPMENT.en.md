## 1. Technical architecture

AS_ExtP uses a **CEP panel (CEF / Chrome 88) + local Node Bridge** architecture:

```
CEP panel (CEF, file://)
  │  8 functional modules + features (Quick Action Bar / desktop pet / external authorization indicator)
  │  Shared/base layer: AEFS · Bridge · ToolRegistry · AST gate (PromptBuilder in client/llm/, ContextManager in client/modules/agent/engine/, container context in client/core/)
  ├── CSInterface.evalScript()  ──►  AE engine (host.jsx + host/api/*.jsx) runs ExtendScript
  ├── Node Bridge (127.0.0.1:9877, HTTP + WebSocket)
  │     ├─ File system (full read/write, including the binary channel)
  │     ├─ External MCP process management
  │     └─ /mcp endpoint (Streamable HTTP transport for external mode)
  └── External mode: external agent ⇄ stdio / HTTP ⇄ Bridge relay ⇄ panel ⇄ AE
```

- **File system (AEFS)**: `client/shared/aefs.js` provides unified file read/write through a multi-level **Bridge → cep.fs → ExtendScript** fallback, with several path safety checks (rejects `%`, control characters, `..` traversal, non-absolute paths and DOS device names; write / delete operations are confined to the safe-directory allowlist).
- **AST compile gate**: every script generated by the AI or saved by the user passes one unified static compile gate before execution — ExtendScript dialect preprocessing → acorn (ES3) parse → type and member allowlist validation → re-emission for execution. The code validated is the code executed, so there is no window in which it could be rewritten after validation. All four entry points (Agent tool calls, the preview pane, JSON tool definitions, script tree / Quick Action Bar) funnel into it, and high-risk forms are blocked at the gate and fed back to the model for rewriting; "Agent module settings → AST Gate Capabilities" shows channel trust, capability-domain switches and the allowlist supplement table. The script tree / Quick Action Bar path (`user-library`) runs in audit mode: the gate only produces a danger list and does not rewrite code (see `client/modules/ast-gate/run.js`).
- **Data directory**: the extension root is read-only; runtime data lives in `%APPDATA%\Adobe\CEP\extensions\AS_ExtP` (scripts, skills, memories, tools, effects, presets and so on). It can be moved to a custom location in the global settings: switching means **copying everything** (if the target already holds data, an overwrite confirmation appears first, and after confirmation the target data is deleted before the copy), and the finishing step **rewrites absolute paths that begin with the old root to the new root** in the copied **library indexes** (`assets/<library>/*.json`) — otherwise, on startup from the new directory, the on-disk scan would treat files with the same names as "unregistered" and index them again (presets / project assets have had duplicate-indexing cases); the old directory is not deleted automatically, so the user has to check it and clean up. **When adding a library**: do not store absolute paths of files inside the library in the index (store relative paths, or compute them from the data directory at runtime); where an absolute path is unavoidable, the migration must do the same rewrite (see `rebaseLibraryIndexPaths` in `client/shared/dataDir.js`).
- **Prompt bus**: the final prompt handed to the LLM is assembled in four layers (System Prompt skeleton → PromptBuilder pipeline → history injection → User Prompt wrapping); modules take part through the standard injection points instead of concatenating prompt strings themselves.
- **Node Bridge**: serves file operations and MCP process management; it exits on idle and is kept alive by a heartbeat while the panel is open. The HTTP endpoint for external mode and the stdio entry share one protocol core, and tool calls are executed serially through the panel (the AE scripting engine is single-threaded).
- **Diagnostic logs**: the panel / Bridge / host / native component processes share ISO timestamps and a per-file size cap (Bridge error lines also carry an `[ERR]` marker); exporting a diagnostic package applies uniform redaction and folds repeated lines by signature (once a signature reaches the threshold only its first line is kept, annotated with the total count and time span). Export is available in the global settings.

### AEFS exceptions

Panel-side (CEP) file I/O always goes through AEFS; a whole-repository review shows the exceptions are concentrated on the host / ExtendScript side — **two categories, seven file-deletion call sites** (zero exceptions in panel-side JS):

1. **Startup-chain self-cleanup (5 sites; structurally cannot go through AEFS)**: `_sweepHandoffLeftovers` in `host/host.jsx` (sweeps orphaned handoff tokens, vbs files and multi-instance probe scripts `.axd`), the `vbsFile` deleted at the end of `startBridge`, `_runAxDetectionProbe` deleting the `.axd` probe script it has just written, `_clearMultiInstanceMarker` deleting `ae_extp_multi_instance.json`, and `_writeHostLoadErrors` deleting the handshake file when there are no failures — AEFS is a panel-side module whose delete interface depends on the bridge / CEP, and these calls run exactly when "the bridge does not exist yet" or while the startup self-checks are wrapping up. Path = the data directory's `temp/handoff` (falling back to the system temp directory), everything deleted is produced by the startup chain itself (handoff token / vbs / `.axd` probe script, multi-instance marker, previous load-error report), and the defence is exact filename regexes, deletion of files only (same-named directories are skipped), and cleanup that only reclaims leftovers whose `mtime` is more than 10 minutes old.
2. **Export flow "clear old, then copy" (2 sites; the ordering makes AEFS unsuitable)**: one each in `exportWholeProject` / `exportCompOrLayer` of `host/api/projectAssetApi.jsx`, clearing the old copy inside the package before footage with the same name is copied in again. The deletion point sits in the middle of an ES-side flow (before the copy), and handing it to the panel would introduce a race between cleanup and export; host-side deletion is therefore kept, but before deleting it replicates AEFS's `_checkPath` and containment check with `_ensureUnderRoot(dstPath, footageDir.fsName)` (rejects `%`, control characters, quotes, DOS device names and `..` segments; the path must be under footageDir), and out-of-bounds paths are only logged, never deleted.

## 2. Environment setup and validation

> **The two ways of getting the files differ in their prerequisites**: the **full Release package is ready to run** (it already contains the Node runtime, the npm dependencies and the prebuilt `.aex` files) — extract it and double-click `tools\install.bat` to finish deployment, and this section can be skipped; a **source clone is not ready to run** and needs the Node runtime below, `npm ci`, `check-env.bat` (which downloads Node / ffmpeg) and, where required, native component builds.

- Node.js **≥ 20.18** (the panel's CEF is Chrome 88 with no Node runtime: `require` / `process` do not exist inside the panel, and file I/O always goes through AEFS)
- Install dependencies: `npm ci`; or double-click `tools\check-env.bat` (checks Node, dependencies, ffmpeg and the AE version item by item and tells you how to fill in what is missing)
- `npm run lint` — ESLint check (`eslint.config.js`)
- `npm run audit:theme` / `npm run audit:family` — audits for hard-coded theme values and extinct failure-mode families (CI gates)
- Public-repository CI (`.github/workflows/ci.yml`) runs two jobs: `lint-and-audits` runs `npm ci` → `lint` → the two audits; `release-tree-check` runs `node tools/release-check.js --public . --public-only` on a clean checkout with no dependencies installed (zero binaries in the public tree, no `node_modules` / `vendor`, complete NOTICES). Any failing step turns it red

## 3. Deploying to CEP

The two scripts have different jobs:

- **First install / ordinary users**: double-click `tools\install.bat`. It detects the installed AE, downloads Node and ffmpeg, writes `PlayerDebugMode`, and deploys the native components automatically when `deploy\Plug-ins\*.aex` is found.
- **Development-time update deployment**: after changing `host` / `client` / `CSXS` or a native component, double-click `tools\deploy.bat` (requires administrator rights; copies these items to `C:\Program Files (x86)\Common Files\Adobe\CEP\extensions\AS_ExtP`). It downloads nothing and touches no registry keys, requires `vendor\` to exist, and prompts you to run `tools\check-env.bat` first when it is missing.

Both scripts fill in a missing `vendor\node_modules` by copying from the root `node_modules` of the source directory — the deployed Bridge resolves its dependencies (docx / xlsx / pdf attachment parsing) from `vendor\node_modules`.

## 4. Localization

The panel interface is localized by a small runtime plus generated locale packs. The Chinese source text is the key (`t('源文')`), so an untranslated string falls back to the Chinese source text instead of disappearing.

> `i18n/`, `tools/i18n/` and `tests/` exist only in the maintainer repository and are not part of the public tree; the public tree only ships the generated locale packs under `client/shared/i18n/locales/`. The commands below are for maintainers.

### Language selection

- Global Settings → **Interface Language** (`globalUiLocale`): stored under `uiLocale` together with the other global settings and mirrored to `localStorage['ae_ui_locale']`, which is where the value is read from at startup.
- Options: **Follow the After Effects interface language** (`auto`), 简体中文 (`zh-CN`), English (`en-US`), 日本語 (`ja-JP`), Deutsch (`de-DE`), 한국어 (`ko-KR`), Français (`fr-FR`), Русский (`ru-RU`).
- `auto` is resolved from CEP's `getHostEnvironment().appLocale`, falling back to `navigator.language` when that fails. A known but unsupported host language resolves to `en-US`; when nothing can be read, `zh-CN` is kept.
- Saving a different value reloads the panel (the settings row says so); no other step is needed.

### Files

| Path | Purpose |
| --- | --- |
| `i18n/keys.json` | Every key queried at runtime (string literals passed to `AEI18n.t(...)` / `AEI18n.html(...)`, plus the text in `client/index.html`), generated by `scan-keys.js` |
| `i18n/translations/en-US.json` | Translations for `en-US` (source text → translation) |
| `client/shared/i18n/locales/en-US.js` | The generated locale pack, loaded statically |
| `client/scripts.manifest.js` | Load order: the locale pack comes first in the i18n group and hands the dictionary to `i18nCore` through `AEI18nPending` |
| `client/shared/i18n/i18nCore.js` | Runtime: `t` / `html` / `err`, language resolution, static DOM translation |
| `client/shared/i18n/i18nHtml.js` | Collects and translates text nodes and allowlisted attributes in HTML templates |
| `client/shared/i18n/errorCodes.js` | Error-code message table |

`i18n/` and `tools/i18n/` are used on the development side only and are not part of the public tree; the public tree only ships the generated locale packs under `client/shared/i18n/locales/`.

### Commands

```bash
node tools/i18n/scan-keys.js                 # Rescan the source tree → i18n/keys.json
node tools/i18n/build-locale.js en-US        # Validate translations → client/shared/i18n/locales/en-US.js
node tools/i18n/check-coverage.js en-US      # Gate: all keys present, no extra keys (exit code 1 on mismatch)
```

`build-locale.js` writes no file and exits with code 1 when a translation is empty, when the `{placeholder}` set differs from the source text, or when a key is not in `keys.json`. After changing interface text, run these three commands in the order above in the maintainer repository, then run `npm test` and `npm run lint`.

### Supported languages

`zh-CN` (source text), `en-US`, `ja-JP`, `de-DE`, `ko-KR`, `fr-FR`, `ru-RU`. The runtime accepts all seven ids; the panel's language selector always lists seven items, independently of which locale packs actually ship with the package. `en-US`, `ja-JP`, `de-DE`, `ko-KR`, `fr-FR` and `ru-RU` are complete (3450 keys each, 100% coverage).

### Scope and limitations

- **Environment fact line (`ENV_LINE`, produced by `envLine()` in `client/modules/agent/engine/prompts.js`)**: the system prompt states the interface language of the host AE (`中文版` / `英文版` / `日文版` / `德文版` / `韩文版` / `法文版` / `俄文版`), taken from `getHostEnvironment().appLocale`; the only source is `client/modules/agent/engine/prompts.js`. It describes a host fact and is unrelated both to the panel interface language and to the language the model answers in.
- **ExtendScript messages**: errors thrown by `host/*.jsx` stay in Chinese. They travel through `CSInterface.evalScript()` as plain strings, take no part in language negotiation, and therefore still read as Chinese under an English interface; only the panel-side error-code mapping is localized.
- **AST gate diagnostics**: `error.reason` / `error.alternative` from `client/modules/ast-gate/` stay in Chinese — they are self-correction input fed back to the LLM (`llmText`). Under any language other than the source text language, panel surfaces (status bar, run-error card, Quick Action Bar) show the localized category sentence from `client/shared/i18n/gateReasons.js`; the original Chinese detail appears only when the interface language is Simplified Chinese.
- **Installer scripts**: `tools/install.bat`, `tools/check-env.bat` and `tools/deploy.bat` print ASCII English only (the scripts switch to `chcp 437`). Script comments may be Chinese; the public tree keeps technical comments, while narrative comments are rewritten or removed by the release comment map.
- **Native component UI**: the user-visible text of `native/hotbox` (AS_Hotbox) and `native/glsl-host` (AS_Effect Host) — the Hotbox filter/settings, effect parameter names, About, error frames and file dialogs — follows the **After Effects host interface language** (`PF_AppGetLanguage`) and is independent of the panel's interface language setting; an unsupported host language falls back to English, and an unreadable host language falls back to Chinese. Logs and internal diagnostics are not translated; warnings that contain technical tokens (such as `[uniform limit reached]`) stay in English, and all other user-facing warnings are already localized.

## 5. Building the native components

Both native components are C++ / CMake projects and **require Visual Studio 2022 (with MSVC) and the Adobe After Effects SDK** — the SDK is not distributed with the repository under its license and has to be obtained from Adobe.

### 5.1 GLSL effect host (`native/glsl-host/`)

```powershell
cmake -S native/glsl-host -B native/glsl-host/build -DAEFX_SDK_PATH="<AE SDK path>"
cmake --build native/glsl-host/build --config Release
```

### 5.2 AE Hotbox (`native/hotbox/`)

```powershell
cmake -S native/hotbox -B native/hotbox/build -DAEFX_SDK_PATH="<AE SDK path>"
cmake --build native/hotbox/build --config Release
```

Build output goes to `deploy/Plug-ins/` by default (override with `-DAE_PLUGIN_OUTPUT=<dir>`). Copy the `.aex` into AE's `Support Files\Plug-ins\` directory and **fully quit and restart AE** for it to take effect. Unit tests for the native logic run with `ctest` inside the build directory and do not involve AE.

## 6. Hotbox development material

> This section covers building, deploying and troubleshooting Hotbox; for end-user usage see the "Native components → AE Hotbox" section of the README.

#### Building the .aex

Prerequisites: AE 2023+ SDK, Visual Studio 2022, CMake 3.20+.

```powershell
# In the repository root
cmake -S native/hotbox -B native/hotbox/build `
  -DAEFX_SDK_PATH="<AE SDK path>" `
  -DAE_PLUGIN_OUTPUT="<repo>\deploy\Plug-ins"
cmake --build native/hotbox/build --config Release
```

Output: `deploy\Plug-ins\AS_Hotbox.aex`.

#### Deploying to AE

1. **Fully quit AE** (a new plug-in only loads after a restart).
2. Copy `AS_Hotbox.aex` into AE's `Support Files\Plug-ins\` directory:

```powershell
Copy-Item "<repo>\deploy\Plug-ins\AS_Hotbox.aex" `
  "<AE install dir>\Support Files\Plug-ins\" -Force
```

3. Make sure the CEP extension is deployed as well (`tools\deploy.bat` or `tools\install.bat`): the hotbox reads scripts and the preset index from the extension data directory, and reads AE's own preset directories directly (lookup rules are under "Data sources" below).
4. Start AE.

#### Verifying the load

After starting AE, check the log `<data dir>\temp\logs\as_hotbox.log`, which should contain:

```
EntryPointFunc OK
window: init ok
hotkey: registered Alt+Q
```

If the hotkey is already taken, the log shows `hotkey: configured ... in use, fallback default` and falls back to `Alt+Q`; if `Alt+Q` is taken as well, `hotkey: default Alt+Q also failed` appears, the plug-in still loads but the hotkey is unavailable (change the key in the settings panel).

#### Configuration file

Configuration is stored in `<data dir>\hotbox\config.json`:

```json
{
  "gesture": {
    "slots": [
      null,
      {"type":"effect","key":"ADBE Gaussian Blur 2","name":"高斯模糊"},
      null,
      null,
      null,
      {"type":"script","key":"C:\\abs\\path\\script.jsx","name":"脚本"}
    ]
  },
  "hotkey": {"mods": 1, "vk": 81},
  "releaseExecute": true,
  "releaseStay": false
}
```

- `slots`: one entry per arc segment of the 6-segment gesture ring (`null` = dynamic slot). The top segment (screenshot entry) and the bottom segment (settings entry) are dedicated and take no slot binding; the settings panel's 4 rows map to the remaining 4 segments (top-left / bottom-left / top-right / bottom-right), and the mapping between arc segments and array indexes is fixed by the layout.
- `hotkey.mods`: bit flags, 1=Alt 2=Ctrl 4=Shift (same as Win32 `MOD_*`).
- `hotkey.vk`: virtual-key code (e.g. 81 = 'Q').
- `releaseExecute`: whether releasing the hotkey runs the selected arc segment (settings row 5, default true).
- `releaseStay`: whether releasing the hotkey keeps the floating window open (settings row 6, default false; see "AE Hotbox" in the README for usage).

The recent-items list is stored in `<data dir>\hotbox\recent.json`.

> The **data directory** defaults to `%APPDATA%\Adobe\CEP\extensions\AS_ExtP`.

### Data sources

The hotbox reads local files directly (it is an AEGP in the same process as AE; it does not depend on the bridge and does not require the extension panel to be open):

| Data | Source | Notes |
|------|------|------|
| Effects | Native AEGP enumeration (`AEGP_EffectSuite4`) | The installed-effect table in AE memory, same source as the Effects menu; display name + matchName are taken |
| Scripts | `agent\scripts\` recursively | `.jsx` / `.jsxbin` |
| Presets (extension library) | `assets\presets\index.json` | `.ffx` files indexed by the panel (the file itself lives in the library directory); name + folder + ffx path |
| Presets (AE factory) | `<AE>\Support Files\Presets\` recursively | Same source as AE's Effects & Presets panel |
| Presets (AE user) | `文档\Adobe\After Effects <version>\User Presets\` recursively | Where AE's "Save Animation Preset" writes; excluded when the directory does not exist |

- **Merging the three preset sources**: priority = extension library > AE user presets > AE factory presets; the de-duplication key = lower-cased name + file byte size, i.e.
  "same name, same size = the same preset copy" (indexing copies the `.ffx` into the library byte for byte, so a copy has the same name and size as its source).
  De-duplicating by name alone is not enough: AE factory presets really do contain two entries with the same name and different content (e.g. "百叶窗" at 191231/26526 bytes,
  "放大" at 43417/75976 bytes), and matching by name alone would swallow real entries. AE-side entries are read, not copied, and are applied through
  `layer.applyPreset(File)`, the same path as library presets (so AE presets can be bound to gesture-ring slots too).
- **Library-side size follows the real file**: the `size` in the index is a snapshot from the moment of indexing and is recalibrated against the file's actual byte count on reload;
  when the file is gone (or the path points at a directory) it is treated as "unknown" — a stale value is never used to dedupe away a real AE-side entry with the same name and size,
  otherwise, after the `.ffx` is deleted from the library, the hotbox would be left with one entry bound to fail while the usable AE preset gets pushed out.
- **Archived entries are excluded from the hotbox**: entries with `archived=true` in the index (the file has been moved into `___archive__` and is physically purged after 7 days)
  are excluded on the same basis as the panel's Quick Action Bar, so they do not push out real AE-side entries with the same name.
- **Locating the AE preset directories**: preferably derived from the plug-in's own module path (`<AE>\Support Files\Plug-ins\...` → install root),
  falling back to asking AE for `app.path` only when the plug-in sits in a non-standard location such as MediaCore (same source as
  `getInstallPath` in the extension's `ae-tools`). When neither is available, only the extension library is used and nothing else is affected.
- The effect list is enumerated inside the AE process (not through ExtendScript, not from a disk index): a newly installed plug-in is searchable without generating any cache.
- `ae-tools\effects_cache.json` is no longer the primary source for the effect list; it is only a fallback when native enumeration returns nothing (AEGP not ready).
- Refresh rules: when the data-source signature (installed effect count + `index.json` mtime + script directory tree + the two AE preset directory trees) is unchanged,
  repeated invocations reuse the in-memory list and pinyin index; adding, deleting or changing scripts/presets, or saving a preset into the user preset directory from inside AE,
  makes the signature mismatch and triggers an automatic reload (no AE restart needed). The signature walk runs on every popup, while a full scan of the factory directory happens only when the signature mismatches,
  so both costs scale linearly with the number of preset / script entries and do not accumulate with the number of popups.
- After the plug-in loads, the first idle period (≥2s) warms up the data once (enumeration + pinyin index), moving the first-load cost off the key-press path.

#### Encoding constraints

- Internal paths and names are UTF-8 narrow strings throughout; files are always opened through wide-character APIs (`utf8ToWide` in `native/hotbox/src/data.h` and the wide-path calls in `log.h`) — a narrow `char*` path is interpreted by the system as ANSI/GBK, so a path containing Chinese cannot be opened.
- AE's AEGP `A_char` strings (effect names / categories) are system ANSI by SDK convention; a single string gives no way to decide the encoding, so batches are classified as ANSI / UTF-8 as a whole before decoding (`isAnsiBatch` / `ansiToUtf8` in `data.h`). New data sources must follow the same rule: never treat `A_char` as UTF-8 directly or build paths from it directly.

### Troubleshooting

#### Log location

`<data dir>\temp\logs\as_hotbox.log` — records plug-in loading, hotkey registration, execution results and error messages. The data directory defaults to `%APPDATA%\Adobe\CEP\extensions\AS_ExtP` (see the "Configuration file" section); if the data directory moves, the log moves with it.

#### Common problems

| Symptom | Checks |
|------|------|
| Nothing happens on the hotkey | Check the log: did `hotkey: registered ...` succeed; is AE in the foreground (it does not trigger in the background) |
| The hotkey is taken | The log shows `hotkey: configured ... in use, fallback default` (falling back to the default combination) or `hotkey: default Alt+Q also failed`; record a new combination in the settings panel. If a key press has **no effect at all** while recording, that combination is held by another program (a system-level exclusive grab, the key never arrives): pick another combination or quit the program holding it |
| The floating window shows `扩展未启动` | The CEP extension is not deployed; run `tools\deploy.bat` or open the AS_ExtP panel in AE |
| Search returns nothing | Was a keyword typed (an empty query lists no entries); are there scripts under `agent\scripts\`; does `assets\presets\index.json` exist |
| Applying an effect fails | Is a layer selected; is a comp open |
| The floating window does not close after releasing the hotkey | `松手停留` (release-stay) is on in the settings panel (`releaseStay` in config.json); close it with Esc / a click outside the window / the hotkey again, or turn it off in the settings panel |
| AE crashes on exit | Check whether `DeathHook` appears in the log; check Event Viewer |
| Positioning is wrong on multiple monitors | The window is clamped to the work area of the monitor under the mouse; on a secondary display the mouse position should not fall outside that display |
| Chinese input misbehaves | The search box is a Win32 EDIT control, so IME composition and candidate lists work; pressing Enter during a composition does not run early |

After changing C++ code:

```powershell

# 2. Rebuild

# 3. Copy the .aex to AE (overwrite)
Copy-Item "deploy\Plug-ins\AS_Hotbox.aex" "<AE install dir>\Support Files\Plug-ins\" -Force

```

After changing ExtendScript (`host/api/effectApi.jsx` and so on):

```powershell

tools\deploy.bat
# No AE restart needed; the new script loads on the next call
```

### Technical architecture

```
┌───────────────────────────────────────────────────────────────────────────────────┐
│ native/hotbox/  AEGP plug-in (C++20 + MSVC, GeneralPlug)                          │
│  ├─ Hotkey engine      RegisterHotKey + hidden message window ← WM_HOTKEY         │
│  │                     → GetCursorPos reads the mouse position                    │
│  ├─ Floating window    WS_POPUP + WS_EX_TOPMOST + layered window transparency     │
│  │                     ├─ Gesture mode: center circle + arc-slice ring (Direct2D) │
│  │                     └─ Search mode: search bar + linear list + filter dropdown │
│  ├─ Execution channel  AEGP_UtilitySuite6::AEGP_ExecuteScript                     │
│  │                     → effectApi.jsx / scriptRunner.jsx                         │
│  └─ Data layer         in-process file reads (std::ifstream + GetFileAttributesW) │
└───────────────────────────────────────────────────────────────────────────────────┘
```

Key constraints:
- The execution channel `AEGP_ExecuteScript` blocks the AE main thread synchronously → keep scripts short; a status hint is shown while one runs.
- Data reads and writes do not go through the bridge: the plug-in reads the configuration file and script index under the data directory directly in-process, and the bridge only serves the panel side.
- Script execution always goes through the sandbox wrapper (`runScriptSandboxed`); no bypass switch is provided.
